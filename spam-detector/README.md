# AI Spam Message Detector

A Streamlit application for classifying SMS messages as **Spam** or
**Legitimate**. It compares Logistic Regression, Multinomial Naive Bayes, and
Linear SVM using the complete SMS Spam Collection bundled in `data/`. The
application runs the saved model locally in the app process and does not use an
external classification API.

## Dataset

The default training dataset is the full, tab-separated SMS Spam Collection from
the [UCI Machine Learning Repository](https://archive.ics.uci.edu/dataset/228/sms+spam+collection).
The original data has no header and stores each label and message as a row.
`data/sample_data.csv` is an 80-message illustration only; it is not the final
evaluation dataset. The demo can be trained explicitly, but its results are
clearly marked as demo-only.

Before splitting, the loader validates labels, removes blank rows and exact
duplicate messages, and rejects identical message text with conflicting labels.
The loader trims outer whitespace but does not collapse case or internal
whitespace. Duplicate removal occurs before splitting to prevent exact duplicate
messages from appearing in both partitions.

## Training and evaluation

Run `python train_model.py` to train all three models on the full bundled UCI
dataset and generate a consistent set of model and evaluation artifacts.

1. Make one stratified 80/20 train/test split (seed `42`) after duplicate removal.
2. Tune each model with five-fold stratified cross-validation using only the
   training partition. Spam F1 is the tuning score.
3. Keep word unigram/bigram and character 3–5-gram TF-IDF vectorizers inside
   each scikit-learn pipeline, so vectorizers are fit within the relevant
   training fold and do not learn from the held-out test data.
4. Select based on training-only cross-validation: highest mean Spam F1 defines
   the best score; models within one standard error are considered comparable,
   with Spam recall used as a tie-breaker.
5. Tune the selected model's decision threshold using nested, training-only
   out-of-fold scores to target 97% Spam recall. Hyperparameters for each
   threshold-validation fold are chosen without that fold's labels. This favors
   catching spam and can increase false positives.
6. Report test metrics from the untouched held-out split. The test data is not
   used for model selection or threshold selection.

The dashboard and generated reports distinguish training-only cross-validation
metrics from held-out test metrics. They do not present in-sample training scores
as estimates of generalization. The confusion matrix labels rows as actual
classes and columns as predictions: a **false positive** is a legitimate message
classified as Spam; a **false negative** is a Spam message classified as
Legitimate.

The Linear SVM's probability estimates are sigmoid-calibrated. The application
shows confidence only when the selected classifier is this calibrated model.
Logistic Regression and Naive Bayes scores are not described as calibrated
confidence. A calibrated estimate is still not a guarantee of correctness.
Performance values are generated by the current training run and saved in
`evaluation_results.json` and `results.txt`; the README does not hardcode a
performance claim.

## Run locally

The checked-in requirements pin the versions used by the project. Use a
compatible Python installation, then:

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
python train_model.py
streamlit run app.py
```

Training on the bundled demo set is optional and is **not** a final corpus
evaluation:

```bash
python train_model.py --demo
```

To run the automated tests:

```bash
python -m pytest -q
```

Training generates these artifacts together from one run:

- `spam_model.joblib` — selected fitted model and metadata.
- `evaluation_results.json` — dataset, split, CV, test, comparison, and
  methodology information.
- `results.txt` — human-readable model comparison and test evaluation.
- `confusion_matrix.png` — selected model's held-out test confusion matrix.

The optional manually labeled diagnostic set is separate from the training
corpus and is not used for model selection or the held-out evaluation:

```bash
python evaluate_representative.py
```

The model artifact uses Python object serialization; load only artifacts created
by a trusted training run. Retrain after changing the Python or ML dependency
versions.

## Limitations and future improvements

- The model reflects an older English-language SMS corpus. Results may differ
  for modern scams, other languages, and other messaging channels.
- Predictions are not always correct. False positives can hide legitimate
  messages, while false negatives can let spam through. Check the original
  message and sender before acting.
- A random stratified test split measures performance on held-out examples from
  the same corpus; it does not establish performance on future or shifted data.
- Calibration estimates depend on representative calibration data and are not
  guarantees.
- Useful next steps include evaluation on a newer, separately sourced,
  time-based dataset; subgroup and calibration analysis; and collecting
  reviewed errors with consent and documented labels.

## Deployment

For Streamlit Community Cloud, include `app.py`, `train_model.py`,
`requirements.txt`, the full dataset, and the generated model/evaluation
artifacts. Keep the Python and dependency versions aligned with the training
runtime; otherwise retrain and regenerate the artifacts in the deployment
environment.
